使用者回報 v1.0.0 的設定裡有幾個功能覺得不必要（每日推播提醒、備份匯出入、演算法派系外露），並且提出核心想法：使用者每天來 App 都是「帶著問題來問」，所以首頁應該改成讓他們自己選想算什麼，而不是自動給一張固定的運勢卡。

討論後確定方向：
1. 砍掉推播、備份、派系設定
2. 首頁改為「選家人 → 選主題 → 看結果」三步流程
3. 運勢文字改用 OpenAI GPT-5.4-mini 動態生成（使用者自備 API Key）
4. 加入查詢歷史與 LLM 結果快取

### 7. Runtime Crash 修復

**起點：** 使用者回報「我一進去按任何按鈕都非常容易跳掉」

**Bug 1 — LazyVerticalGrid 無限高度 crash**

TopicPickerScreen 裡 LazyVerticalGrid 放在 Column 裡沒有限制高度，Compose 傳入 infinity maxHeight 導致 crash。

修復：加上 `Modifier.weight(1f)` 限制 LazyVerticalGrid 高度。

**Bug 2 — LoadingCard fillMaxSize 在可捲動父層**

TopicResultScreen 的 LoadingCard 在 `verticalScroll` 的 Column 裡用了 `fillMaxSize`，constraint 無限大。

修復：改 `fillMaxWidth` + `heightIn(min = 240.dp)` 在內層 Column。

**Bug 3 — Migration SQL 格式不匹配**

`INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT` vs Room 預期的 `INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL`，驗證 hash 失敗。

修復：對齊 SQL 欄位修飾詞順序。

**驗證：** `assembleDebug` 編譯通過，APK 安裝後不再 crash。

## 學到 / 確認的東西

### 1. OpenAI Responses API 的 json_schema 結構化輸出

GPT-5.4-mini 支援 `text.format.type = "json_schema"` 強制結構化輸出。schema 定義 required/properties 後，模型輸出保證符合格式。解析路徑：`output[0] (type=message) → content[0] (type=output_text) → text (JSON string)`。

### 2. Compose LazyVerticalGrid 必須有限制高度

放在 Column 裡的 LazyVerticalGrid 如果不加 `weight(1f)` 或固定高度，Compose 會傳 infinity maxHeight 直接 crash。這跟 RecyclerView 不同（RV 會自己處理）。

### 3. Room Migration SQL 格式要精確對齊

Room 會驗證 migration 後的 table schema hash，SQL 修飾詞順序不同（`NOT NULL PRIMARY KEY` vs `PRIMARY KEY ... NOT NULL`）就會 hash 不匹配導致 crash。
